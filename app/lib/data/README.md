# 데이터 계층

로직 계층의 저장 인터페이스를 SQLite(sqflite)로 구현한다.
DB 스키마·마이그레이션·트랜잭션·직렬화는 이 계층에 한정한다.
`SqliteRoutineStore`에 설정·루틴·기상 기록·실행 스냅샷 저장을 구현했다.
Android에서는 `openDefault()`로 앱 내부 DB를 열고, 호스트 테스트는 명시적 파일 경로와 `databaseFactoryFfi`를 주입한다.

스키마 1의 테이블은 `settings`, `routines`, `wake_records`, `routine_runs`다.
ID·상태·검색 시각·실행 버전은 컬럼이며 상세 모델과 단계 순서는 버전이 있는 스냅샷에 저장한다.
관측·실행 시각은 epoch 마이크로초로 보존하고 읽을 때 UTC `DateTime`을 반환한다. 화면 표시에는 `.toLocal()`을 사용한다.
시간대가 없는 설정 시각은 하루 안의 분 값으로 보존한다.

루틴 수정·삭제는 과거 실행을 변경하지 않는다. 같은 기록 재저장은 멱등적이며 오래된 실행 버전과 종료 기록의 덮어쓰기, 확정·취소 기록의 후보 역행은 거부한다.
알 수 없는 스냅샷 버전이나 손상 데이터는 오류로 반환하며 조용히 초기화하지 않는다.

실제 파일 DB 재개방·입력 보존·불변 기록·상태 보호·손상 처리를 호스트 자동 테스트로 검증했다.
T04·T05의 UI 오류 안내·실제 SQLite 실패 및 에뮬레이터 관측 결과는
[UI 규약 점검](../../../docs/t04-t05-ui-audit.md)에 구분해 기록한다. 실제 물리 기기 검증과 구분한다.

## 연결 소유권과 종료 책임

- 앱 조립 계층이 DB 파일당 `SqliteRoutineStore` 하나를 열어 소유한다. 화면·서비스에는 `RoutineStore`로 동일 객체를 주입한다.
- 주입받은 화면은 뒤로가기·dispose에서 공유 저장소를 닫지 않는다. 자신이 만든 입력 컨트롤러·구독만 정리한다.
- 앱의 저장소 소유자가 새 작업을 받지 않도록 한 다음 소비자 작업·구독을 정리하고, 마지막에 `close()`를 호출한다. 이후에는 저장소를 다시 사용하지 않는다.
- 일반 Android 앱에서는 OS가 프로세스를 종료할 수 있다. 종료 콜백 실행에 저장을 미루지 않고 각 저장 작업의 완료를 기다린다.
- 테스트·독립 실행 화면이 직접 저장소를 열었다면 해당 실행 경계가 소유자다. 다른 소비자가 없는 경우에만 자신이 연 저장소를 닫는다. 주입받은 경우와 구분한다.

### 같은 파일을 두 번 여는 경우

현재 `open()`은 sqflite 기본 `singleInstance`를 사용한다. 같은 factory·같은 DB 파일 경로로 A와 B를 열면 Dart wrapper가 달라도 내부 Database 연결은 공유된다. **A.close() 후 B도 `database_closed`로 실패할 수 있다.** wrapper별 독립 연결·참조 카운트·화면별 close를 보장하지 않는다. 이 동작을 우회하려고 화면마다 DB를 다시 열거나 `singleInstance` 설정을 바꾸지 않는다.

실제로 서로 다른 DB 파일은 별도 수명이다. 독립 테스트는 임시 디렉터리·다른 파일을 사용한다.

### T04·T05 및 후속 앱 기동 통합

UI는 이미 연 저장소를 주입받는 경로를 사용한다. 기본 생성 함수로 다시 연 wrapper를 화면이 닫는 방식과 앱 소유 저장소 주입을 섞지 않는다. 후속 #24의 앱 기동 계층에서 세션과 UI에 같은 소유 저장소를 전달하고, 화면 이탈 뒤에도 세션이 계속 읽고 쓸 수 있는지 통합 검증한다.

이 PR은 연결 동작과 소유권 계약을 명시한다. UI 파일·앱 기동 코드는 후속 PR 범위이며, 현재 문서·호스트 테스트만으로 그 통합이 완료됐다고 판단하지 않는다. 활성 계획의 설정·선택 루틴 변경은 후속 세션 API 경계도 따라야 한다.

검증: `test/data/store_ownership_test.dart`에서 같은 파일의 wrapper 간 종료 영향, 서로 다른 파일의 독립성, 한 저장소를 공유한 뒤 소유자 종료·재개방 시 데이터 보존을 실제 SQLite 파일로 확인한다. Android 프로세스 수명·실제 화면 dispose는 이 호스트 시험과 별도다.
