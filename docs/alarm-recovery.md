# 알람 변경 실패와 복구 (#14)

예약 변경은 직렬로 처리한다. 새 예약이 실패하면 부분 적용 가능성이 있는 새 ID를 먼저 취소하고, 이전 예약이 미래이며 권한이 유지될 때 복원을 시도한다. 복원 성공도 설정 변경 성공이 아니므로 AlarmApplyFailure를 반환한다.

- request: 실패한 변경 대상
- previous: 변경 전에 추적하던 예약
- previousRestored: 이전 예약을 다시 적용한 것을 확인한 경우만 true
- cause/recoveryError: 최초 실패와 복구 실패 구분
- scheduled: 복원 성공 시 이전 예약, 보장하지 못하면 null
- lastFailure: 성공한 적용·취소 전까지 최근 변경 실패 확인

복구 시각 판단에 clock을 주입할 수 있다. 만료된 이전 알람을 다음 날로 옮기거나 권한이 없는 상태에서 복원하지 않는다. 실패 원인을 숨기고 이전 예약을 유지한 것처럼 표시하지 않는다. 호출자는 실패를 사용자에게 안내하고 저장된 변경 의도를 재시도해야 한다.

네이티브 알림 버튼에서 다시 울림·해제를 처리하면 invalidate()로 Dart 캐시만 무효화한다. OS 예약을 취소하거나 원래 계획으로 재예약하지 않는다. 후속 세션·기동 계층에서 보존 이벤트와 실패 정보를 소비한다.

wakeConfirmed()는 해당 알람만 취소한다. 날짜를 포함한 단발 예약이며 다음 날 자동 반복 예약은 구현하지 않았다. 다음 날을 테스트하려면 새 목표 날짜로 계획을 저장하고 예약하는 절차를 명시해야 한다.
