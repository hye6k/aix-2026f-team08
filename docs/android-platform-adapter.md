# Android 앱용 플랫폼 어댑터 (#22)

## 연결 API

`AndroidMorningPlatform`은 `AlarmPort`, `ActivitySignalPort`를 구현한다. 예약에는 고유 ID와 날짜를 포함한 미래 시각을 전달한다. `permissions()`는 정확한 알람·알림 권한을 따로 반환한다. 권한 요청 메서드는 사용자 조작에서 호출한 뒤 앱 복귀 시 권한을 다시 조회한다. 설정 화면을 열었다는 사실은 승인 결과가 아니다.

알람 알림의 해제와 5분 다시 울림은 네이티브 수신기가 처리한다. 두 동작 모두 기상 확정이 아니다. 화면 켜짐만 `WakeSource.screenOn` 신호로 전달한다. 후보 판정·사용자 확인·루틴 시작은 애플리케이션 계층의 책임이다.

알람 동작은 이벤트 ID와 함께 로컬에 남는다. 소비자는 스트림을 구독하고 `pendingAlarmEvents()`를 조회하여 ID로 중복을 제거한 뒤 처리 완료 시 `acknowledgeAlarmEvent()`를 호출한다. 화면 켜짐은 저장하지 않는다. 모든 구독이 해제된 어댑터는 재사용하지 않고 새 인스턴스로 연다.

## 지원 범위와 남은 검증

- 화면 신호 수신기는 Flutter 엔진이 살아 있는 동안 등록된다. 프로세스 종료 후 지속 감지는 구현하지 않았다.
- 알람 수신기는 main에 있고 실험용 debug 수신기와 별개다. 재부팅 복원·강제 종료 후 동작·제조사 절전 예외 처리는 구현하지 않았다.
- 정확한 알람과 알림이 모두 허용되어야 예약한다. 알림 채널 차단도 거부로 반환한다. 예약 후 권한이 바뀌면 실제 결과를 재검증해야 한다.
- 오래된 발생 시각의 알람과 이미 처리한 알림 동작은 현재 예약 상태를 확인하여 무시한다.
- 자동 테스트와 에뮬레이터 실행은 소리·진동의 실제 수신 및 Deep Doze 검증을 대신하지 않는다. #17의 이전 검증 도구 결과를 이 어댑터의 실기기 결과로 전용하지 않는다.

## 검증 방법

`bash scripts/check.sh`로 Dart 경계를 검사하고 `flutter build apk --debug --no-pub`로 네이티브 연결을 빌드한다. 실제 기기에서는 알림·정확한 알람 각각 거부, 예약·변경·취소, 알람 발생·해제·다시 울림, 화면 켜짐, 앱 실행·백그라운드·프로세스 종료·재부팅 상태를 구분해서 기록한다. 기상 기록이 알림 버튼만으로 확정되지 않는지도 확인한다.

2026-11-07 API 36 에뮬레이터에서 제품 채널의 미래 예약 → 네이티브 알람 발생 → 보존 이벤트 조회·확인 처리, 발생 전 예약 취소, 화면 껐다 켜기 신호 전달을 확인했다. 검증 전용 로컬 진입점으로 실행했으며 현재 기본 화면에서 이 조작을 제공하는 것은 아니다. 소리 출력과 실제 진동은 검증하지 않았다.

## 명세 대조 보완 (2026-11-07)

T17의 기상 후보 확인 요청을 위한 별도 알림 채널과 showWakeCandidate/clearWakeCandidate 호출을 추가했다. 기상 알람의 소리 반복·해제·다시 울림과 별개이며 알림을 누르면 앱을 연다. 후보가 확정·취소되면 조립 계층에서 알림을 제거해야 한다. 후보 알림도 알림 권한·채널 차단 오류를 반환한다. 표시 호출 자체가 기상 확정은 아니다. 채널 경계 집중 테스트는 10건이다.
