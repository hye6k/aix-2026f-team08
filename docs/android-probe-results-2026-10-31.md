# Android API 36 가상 기기 관측 — 2026-10-31

관련 이슈: [#7 / T02 준비](https://github.com/hye6k/aix-2026f-team08/issues/7), [#4 / T01](https://github.com/hye6k/aix-2026f-team08/issues/4).

## 환경과 판정 범위

- Android Emulator 37.2.13, KVM 가속, API 36 / Android 16, `sdk_gphone64_x86_64`.
- 최초 부팅 뒤 System UI 응답 지연이 있었으며, 이후 기본 Flutter 화면의 정상 렌더링을 확인했다. 렌더러 설정이나 앱 UI 코드를 바꾸지 않았다.
- 기본 앱 실행 화면: [에뮬레이터 스크린샷](images/android-emulator-home-2026-10-31.png).
- 관측 도구와 절차: [android-probe.md](android-probe.md).
- 최종 원시 결과: [13개 관측 JSON](test-results/android-api36-2026-10-31.json).

13개 사례에서 **기대 관측이 성립**했다. 강제 종료·재부팅 뒤 미수신 같은 제한의 관측도 포함되므로 모든 앱 상태를 지원한다는 의미가 아니다.
기상 확인은 수행하지 않았으며 OS 활동 신호를 실제 기상 확정으로 저장하지 않았다.
가상 기기는 `-no-audio`로 실행했다. 알림·진동 API 호출 로그와 실제 소리·진동을 구분하며 실물 동작은 미검증이다.

## 관측 결과

| 조건 / 조작 | 관측 | 판정 범위 |
|---|---|---|
| 앱 전면, 화면 끄기·켜기 | `SCREEN_ON` 수신 | OS 신호만 확인, 실제 기상 아님 |
| 정확한 알람 권한 거부 | 예약 차단, 거부 로그 | ADB appops 변경 사용 |
| 앱 전면 예약 | 알람 Receiver 수신 | 실제 소리·진동 미검증 |
| Activity가 유지된 백그라운드 | 화면 신호·알람 수신 | Launcher가 전면인 상태를 함께 확인 |
| 예약 취소 | 기존 예약 시각을 지난 관측 구간에 수신 없음 | 8초 예약 취소 후 10초 관측 |
| 같은 PendingIntent 재예약 | 기존 시각에 미수신, 새 시각에 1회 수신 | 중복 예약 여부 확인 |
| 백그라운드 프로세스 제거 | PID 부재 확인 후 새 PID에서 알람 수신 | `am kill` 사용. 설정의 강제 종료와 구분 |
| 설정의 강제 종료에 해당하는 `am force-stop` | 예약 알람 미수신 | 이 상태의 알람 지원 성공으로 표기하지 않음 |
| 알림 권한 거부 | 알람 Receiver 수신, 알림 거부 로그 | 알림 표시 성공으로 표기하지 않음 |
| 정확한 알람 권한 철회 | 관측 구간 미수신, 이후 새 예약 차단 | ADB 제어이며 수동 권한 화면 조작과 구분 |
| 검증 앱의 단일 Task 제거 | Task 부재 확인, 알람 수신, 화면 신호 미관측 | ADB `am stack remove` 사용, 최근 앱 UI 스와이프 검증과 구분 |
| 재부팅 | 부팅 완료 후 예약 알람 미수신 | 현재 도구에는 부팅 후 예약 복원 구현 없음 |

초기 `am kill` 시도에서는 PID가 남아 있어 종료 뒤 동작을 판정하지 않았다. 백그라운드 전환과 PID 부재를 확인하는 절차로 보완한 뒤 최종 결과를 작성했다.
각 시험은 권한과 예약 성공 등 전제 조건을 확인한다. 앞선 권한 철회 상태를 뒤 시험의 실패로 혼동하지 않도록 시험별로 설정한다.

## 관측 도구의 수정과 회귀 확인

Activity 복원 시 예전 Intent의 예약 명령이 다시 실행되는 현상을 발견했다.
복원에서는 기존 명령을 재실행하지 않고 새 Intent 명령은 처리 후 소비하도록 수정했다.
최종 로그에서 `ACTIVITY_RESTORED; NO_COMMAND_REPLAY`와 새 예약 1회를 확인했다.
화면 리시버의 관측 범위 표기도 Activity 생존 기간으로 바로잡았다.

## 아직 확인하지 않은 것

- 프로세스·Activity 제거 후 동적 화면 리시버로 연속 감지하는 제품 구현. 별도 재시험에서 제거 뒤 화면 신호가 관측되지 않았다.
- 실제 스마트폰의 소리·진동·제조사별 백그라운드 전원 정책.
- UI 스와이프에 의한 최근 앱 제거, 화면 잠금의 다양한 보안 설정.
- Doze에서의 동작: 별도 강제 진입 시도는 `Unable to go deep idle; stopped at INACTIVE`였고 확인한 상태는 `ACTIVE`였다. 알람 수신은 관측했지만 Doze 검증 성공으로 간주하지 않는다. [원시 결과](test-results/android-api36-idle-2026-10-31.json).
- OS 신호→Dart 기상 후보→사용자 확인→실행의 제품 통합. 호스트 테스트의 주입 이벤트와 구분한다.
