### 3-1. 알람 취소 및 재예약

- 알람 취소 명령을 실행하고 기존 예약 알람이 수신되지 않는 것을 확인하였다.
- 알람 재예약 시 기존 예약이 교체되고 변경된 시각에 알람이 1회 수신되는 것을 확인하였다.
- 재예약 과정에서 중복 수신은 관찰되지 않았다.
- 마지막 추가 테스트에서는 `ALARM_CANCELLED` 로그를 확인하였다. 다만 해당 예약은 예정 시각까지 미수신 여부를 별도로 관찰하지 않았다.

### 3-2. 알림 및 정확한 알람 권한

**알림 권한 거부**

```text
ALARM_RECEIVED
NOTIFICATION_PERMISSION_DENIED
```

알람 수신 이벤트는 발생했지만 알림은 표시되지 않았다.

**정확한 알람 권한 거부**

```text
EXACT_ALARM_PERMISSION_DENIED
```

정확한 알람 권한 거부를 감지하고 새 예약을 차단하는 것을 확인하였다.

### 3-3. 삼성 절전 모드

삼성 갤럭시의 절전 모드를 활성화하고 앱 배터리 최적화 설정을 유지한 상태에서 60초 알람을 테스트하였다.

```text
1793709170514 ALARM_SCHEDULED at=1793709230513
1793709230522 ALARM_RECEIVED; NOT_WAKE_CONFIRMATION
1793709230528 NOTIFICATION_REQUESTED; ACTUAL_SOUND_UNVERIFIED
1793709230532 VIBRATION_REQUESTED has_vibrator=true; ACTUAL_VIBRATION_UNVERIFIED
```

- 예약 시각 대비 약 9ms 뒤 알람 수신 로그 기록.
- 실제 알림 표시 확인.
- 실제 진동 발생 확인.
- 실제 알람 소리 출력은 별도 검증하지 않았다.

### 3-4. Deep Doze 비교 테스트

Deep Doze 진입 조건의 차이를 확인하기 위해 알람 예약 여부에 따른 비교 테스트를 수행하였다.

| 테스트 조건 | 실행 결과 |
|---|---|
| 알람 미예약 상태 | `force-inactive` → `force-idle deep` 실행 후 `IDLE` 확인 |
| 180초 알람 예약 상태 | 동일한 진입 시도에서 `INACTIVE`에 머무름 |
| Deep Doze 상태의 실제 알람 수신 | 미검증 |

알람을 예약하지 않은 상태에서는 Deep Doze 강제 진입에 성공하였다.

반면 180초 알람을 예약한 상태에서는 다음 메시지가 반복적으로 발생하였다.

```text
Unable to go deep idle; stopped at INACTIVE
```

두 조건에서 결과 차이가 확인되었으나, 알람 예약이 직접적인 실패 원인인지는 확정하지 못했다.

따라서 Deep Doze 상태에서의 실제 알람 수신은 미검증으로 유지한다.

## 5. 검증 시 유의 사항 및 제한

- `ALARM_RECEIVED`는 알람 이벤트 수신 기록이며 실제 기상 성공을 의미하지 않는다.
- `SCREEN_ON`은 화면 켜짐 신호이며 사용자의 실제 기상 여부를 의미하지 않는다.
- `NOTIFICATION_REQUESTED` 및 `VIBRATION_REQUESTED`는 API 요청 기록이므로 실제 출력 결과와 구분해야 한다.
- 강제 종료 및 재부팅 이후 알람 미수신은 현재 Debug 테스트 도구에서 확인한 제한 사항이다.
- 삼성 절전 모드 테스트 성공을 모든 제조사 및 모든 Android 절전 상태에 일반화하지 않는다.
- Deep Doze 진입과 실제 알람 수신은 별개의 검증 항목으로 관리한다.
