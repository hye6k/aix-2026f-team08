## 2026-10-31 후속 개발 검증

- 준비한 기능 브랜치를 합친 로컬 검증에서 정적 분석과 테스트 45건이 통과했다. 이 중 4건은 실제 SQLite 파일을 재개방하며 설정→테스트 신호→기상 확인→루틴→복구→도착 계산→기록 보정의 연결을 검증한다.
- 이 테스트에서 활동 신호는 `WakeSource.test`로 명시한 주입 이벤트다. 실제 Android 활동 감지 성공으로 기록하지 않는다.
- 전체 변경 상태의 Android debug APK 빌드를 통과했다.
- 별도 개발 도구 `ProbeActivity`/`ProbeAlarmReceiver`의 debug 및 release APK 빌드를 통과했다. 실제 APK manifest 검사로 실험 Activity·Receiver와 알람·알림 권한이 release에 포함되지 않음을 확인했다.
- Android Emulator 37.2.13과 API 36 이미지를 설치했다. 최초 소프트웨어 모드 실행은 정상 부팅 전에 종료 코드 139로 끝났으나, 사용자 승인·적용 후 KVM 가속으로 정상 부팅했다.
- API 36 가상 기기에서 초기 Flutter 화면 실행과 화면·알람·권한·프로세스 상태 관측 13건을 확인했다. 위 표는 실기기 검증이므로 미검증을 유지한다. 실물 소리·진동·제조사 정책과 실제 Doze는 확인하지 않았다.
- 재현 방법은 `docs/android-probe.md`의 별도 도구 PR을 따른다. T01 #4와 T02/T17 전체 완료 판정은 실제 관측 후 진행한다.

## API 36 에뮬레이터 관측과 저장 복원 (2026-10-31)

- Android 16/API 36 Google APIs x86_64, KVM 가속, 헤드리스·오디오 출력 없음.
- 기본 Flutter 화면 실행을 확인했다. #7 PR의 `docs/android-probe-results-2026-10-31.md`와 원시 JSON에 13개 관측·재현 조건을 기록했다.
- 전면·Activity가 살아 있는 백그라운드에서 동적 화면 리시버 신호와 예약 알람 수신을 확인했다. Activity/프로세스 제거 뒤 화면 신호 미수신, 강제 종료·재부팅 뒤 알람 미수신도 관측했다. 일부 미수신은 재현한 제약이며 지원 성공이 아니다.
- exact alarm/알림 권한 거부·철회, 취소·교체 예약, 프로세스 제거 뒤 알람 수신을 구분해 확인했다. 실물 소리·진동과 진짜 Doze는 미검증이다.
- Android 실제 sqflite 플러그인으로 서로 다른 프로세스(PID 4442 → 4548)의 쓰기·읽기 2건을 통과했다. 별도 테스트 DB에서 후보·진행/중단 상태·시각·예상 도착·중앙값 보정·완료 저장을 확인했다.
- 통합 회귀 PR의 `docs/android-store-validation.md`에 절차를 기록했다. 기상 신호는 `WakeSource.test`이며 사용자 화면·실제 OS 감지와 연결한 전체 흐름은 검증하지 않았다.
- T02/T17의 최종 방식 채택·기기 지원 확정과 이슈 종료는 별도 완료 조건으로 남긴다.
