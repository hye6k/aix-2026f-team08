# SQLite 세션 복원과 앱 기동 연결 (#24)

`main`은 `MorningBootstrap`을 실행한다. DB를 열어 활성 상태를 복원한 뒤 기존 앱을 `MorningScope`로 감싼다. 기존 설정·루틴 화면은 런타임이 소유한 저장소를 빌려 쓰며 화면을 닫아도 연결을 닫지 않는다. 초기 저장소 조회 실패 시 재시도 화면을 표시한다. 계획·기상·진행 화면과 그 세션 연동은 후속 UI 작업이다.

화면은 `MorningScope.of(context).session`에서 [세션 API](morning-session-api.md)를 얻는다. `changes` 구독과 최초 `view` 조회를 함께 사용한다. `platformError`와 `permissions`는 런타임의 ValueListenable이며 화면에서 권한 안내·재시도에 연결할 수 있다. 권한 요청은 사용자 조작에서 `runtime.platform.request…Permission()`을 호출한다. 설정 복귀 시 실제 권한을 다시 조회하며 요청 호출 자체를 승인으로 취급하지 않는다.

## 저장과 복원

SQLite v2는 기존 v1 테이블과 기록을 유지하고 단일 활성 회차 `session_context`를 추가한다. 목표 날짜는 달력 날짜와 UTC 여부를 저장한다. 기상·실행 스냅샷은 기존 버전 형식을 사용한다.

세션 참조와 전달받은 설정·루틴·기상·실행을 하나의 트랜잭션으로 쓴다. 오래된 세션 버전, 없는 참조, 확정되지 않은 기상의 취소 대기를 거부한다. 실패하면 전달받은 다른 변경도 롤백한다. 활성 참조가 없는 v1 기록을 임의로 현재 실행으로 선택하지 않는다.

기상 확정 후 OS 취소 실패 시 확정 기록과 취소 대기를 남긴다. 재시도 또는 다음 기동에서 취소를 다시 시도한다. 앱 시작·재개만으로 이미 해제하거나 다시 울린 알람을 기존 계획 시각으로 재예약하지 않는다.

## 수명 관리

런타임이 DB·화면 신호·네이티브 이벤트 구독을 소유한다. 앱 복귀 시 권한과 보존 알람 이벤트를 조회한다. 이벤트 ID로 중복 처리 후 확인 처리하며 알림 버튼 동작을 기상 확정으로 바꾸지 않는다. 전경에서는 30초마다 시간 기반 예상을 갱신한다. 실시간 초 표시가 필요한 화면은 별도 화면 갱신을 연결할 수 있다.

종료 시 새 작업 유입을 막고 진행 중인 새로고침·이벤트 처리·세션 조작을 기다린 뒤 구독과 DB를 정리한다. 플랫폼 접근 실패는 저장된 정보 접근을 유지하면서 별도 오류로 노출한다. DB 조회·무결성 오류는 조용히 초기화하지 않는다.

## 검증 범위

실제 SQLite 파일 재개방과 v1 마이그레이션·롤백은 호스트 자동 테스트로 검증한다. 앱 조립·기동 오류 재시도·구독 종료는 플랫폼 대역으로 검증한다. 제품 Android 채널의 에뮬레이터 결과와 실제 기기의 소리·진동·절전 결과는 별도로 기록한다. #17의 실제 기기 통합 검증 및 UI 담당자의 화면 연결은 남는다.

2026-11-07: 호스트 전체 Flutter 108건·Python 20건과 정적 분석, 일반 앱 debug·release 빌드를 통과했다. API 36 에뮬레이터의 Android SQLite에서 저장 → 프로세스 종료 → 재실행 복원을 확인했고 이후 종료·확정을 저장했다. 입력 신호는 검증용 진입점에서 주입했으며 실제 화면 감지와 구분했다. 별도 제품 채널 실험에서는 실제 화면 껐다 켜기 신호가 전달되는 것을 확인했다.

## 요구 대조 보완 (2026-11-07)

알람 적용 대기의 예약·취소 의도와 대상 시각을 SQLite에 보존한다. 이전 v2 회차에 해당 필드가 없으면 적용 대기 없음으로 읽는다. 화면은 세션의 alarmUpdatePending/alarmPendingAt을 재시도 안내에 사용한다.

현재 선택된 루틴의 일반 저장·삭제와 활성 설정의 일반 저장은 거부한다. 기존 편집 화면은 아직 세션 configure에 연결되지 않아 활성 계획이 있을 때 해당 변경을 저장할 수 없으며 일반 저장 실패를 표시한다. 후속 UI 연동에서 계획과 알람을 함께 갱신하도록 연결해야 한다. 마지막 선택 루틴의 계획 해제·삭제 흐름도 아직 없다. 이 제한으로 T05 전체가 완료됐다고 판단하지 않는다.

후보 상태를 구독하여 별도 Android 확인 요청 알림을 표시한다. 반복 후보는 같은 요청으로 묶고, 확정·취소·회차 변경 시 제거한다. 알림 실패는 후보 저장을 되돌리지 않고 platformError에 전달한다. 종료 직전에도 저장된 최종 후보 상태를 반영하며 OS 요청 실패는 다음 기동에서 다시 동기화한다. 사용자 확인 화면 연결은 별도다.
