# 기기 독립 개발 계약과 PR 제출 순서

관련 이슈: [#6](https://github.com/hye6k/aix-2026f-team08/issues/6).

## 원래 완료 조건 유지

5주차의 T01 → T02 → T03 이후 통합 흐름은 유지한다.
기기 독립 모델·저장·계산·상태 처리를 별도 구현 단위로 준비하되, 테스트 이벤트 통과를 실제 Android 감지·알람 성공으로 간주하지 않는다.
실제 기기 검증이 남은 T01/T02/T17과 UI 연결이 필요한 전체 흐름은 완료 처리하지 않는다.

## 공통 모델

`app/lib/domain/models.dart`는 Flutter·DB·Android API를 import하지 않는 순수 Dart 코드다.

| 모델 | 의미 |
|---|---|
| `ClockTime` | 날짜 없는 로컬 시각. 00:00~23:59 검증 |
| `AppSettings` | 도착·이동·수면·권장/수동 기상·감지 시간 구간 |
| `Routine` / `RoutineStep` | 고유 ID와 순서를 가진 준비 단계. 예상 시간은 양수 |
| `WakeRecord` | 관측 신호와 후보/확정/취소 상태. 기상 시각과 확인 시각 구분 |
| `RoutineRun` / `StepExecution` | 실행 당시 단계 스냅샷·진행 상태·시각·갱신 버전 |
| `DailyPlan` | 권장 기상과 실제 알람, 취침·출발·도착 날짜 시각 |

미확인 후보에 확정 기상 시각을 넣을 수 없다. 실행 스냅샷의 중복 단계·잘못된 순서·역행 시각을 거부한다.
수동 루틴 시작은 확정 기상 기록을 만들지 않는다.

## 의존성 경계

`ports.dart`의 `RoutineStore`는 설정·루틴·기상·실행 저장 계약이다.
`AlarmPort`는 권한 조회·예약·취소 계약이며 실패는 호출자에게 반환한다.
`ActivitySignalPort`는 시각과 출처를 가진 활동 신호 스트림이다. 신호 자체는 기상 확정이 아니다.

표현 계층의 화면 모델은 생성자로 저장·플랫폼 구현을 주입받고 로직을 호출한다.
실행 ID·단계 ID·기상 기록 ID는 호출 계층에서 안정적인 고유값으로 공급한다.
`WakeTracker`에 전달하는 이전 후보는 같은 계획 회차의 기록이어야 하며 다음 회차의 기록과 혼합하지 않는다.
날짜/시각 계산에는 대상 도착 날짜를 명시하고, 감지 구간 판단에는 사용자 로컬 시각을 전달한다.

## 상태 복구와 화면 연결

- 시작 시 저장소에서 설정·루틴·기상 기록·실행 스냅샷을 읽는다.
- 미확인 후보는 후보로 복원하고 확정/취소 기록은 재확인 대상으로 만들지 않는다.
- 실행 중인 스냅샷은 저장한 시작 시각과 현재 시각으로 경과 시간을 계산한다. 앱을 닫아 둔 시간을 제외하지 않는다.
- 종료한 실행은 실행 중으로 복원하지 않는다.
- 단계 조작은 단계 ID를 전달하고 반환된 스냅샷을 저장한다. 재전송된 이전 단계 조작으로 다음 단계를 완료하지 않는다.
- 계산·상태 처리·저장 오류를 화면에서 안내한다. 저장 실패 후 성공한 것처럼 표시하지 않는다.

UI T04/T05/T07/T11/T16과 테스트 시나리오 T12/T13의 담당은 기존 활동지를 따른다.
이 계약은 담당 화면에서 연결할 수 있는 로직과 저장 경계를 제공한다.
