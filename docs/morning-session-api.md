# 화면에서 사용하는 아침 세션 API (#23)

`MorningSession`은 순수 Dart이며 Android·SQLite·위젯을 참조하지 않는다. `SessionStore`, `AlarmPort`, `ActivitySignalPort`, 현재 시각과 ID 생성기를 주입한다.

| 호출 | 결과 |
|---|---|
| `initialize()` | 설정·활성 회차·후보·실행 복원, 화면 신호 구독. OS 알람을 무조건 재예약하지 않음 |
| `configure(settings:, routine:, arrivalDay:)` | 선택 루틴과 설정·목표 날짜를 함께 저장하고 계획 알람 적용. 진행 중인 실행은 먼저 종료해야 함 |
| `view` / `changes` | 현재 계획·후보·실행·조건부 도착 예상·오류·권한 거부 결과 |
| `observe(signal)` | 해당 날짜의 감지 구간에서 후보 생성. 시작 포함·종료 제외 |
| `confirmWake()` / `cancelCandidate()` | 후보 확인 또는 취소. 확인만으로 루틴을 자동 시작하지 않음 |
| `recordManualWake(at)` | 사용자가 입력한 과거 기상 시각 보존 |
| `startRoutine()` | 선택 루틴 시작. 수동 시작은 기상 확정이 아님 |
| `completeStep(id)` / `skipStep(id)` / `stopRoutine()` | 단계 진행·건너뛰기·종료와 실행 스냅샷 저장 |
| `snooze()` / `dismissAlarm()` | 5분 다시 울림·알람 해제. 기상 기록 변경 없음 |
| `retryAlarm()` | 취소 대기 재시도 또는 저장된 미래 계획 알람 적용 |
| `nativeAlarmChanged()` | 네이티브 알림 버튼 동작 후 예약 캐시 무효화. 다시 예약하지 않음 |
| `refreshClock()` / `close()` | 시간 기반 예상 갱신 / 구독 종료. DB 수명은 조립 계층이 관리 |

각 조작의 Future를 기다리고 실패를 화면에 표시한다. 저장 실패는 활성 참조와 기록 모두 롤백되어야 하며 `SessionStore.commitSession` 구현에서 이를 보장한다. DB 저장 후 OS 예약이 실패할 수 있으므로 오류가 나도 이미 저장된 설정·기상은 유지된다. 기상 확정은 먼저 저장하고 알람 취소 실패는 취소 대기로 보존하여 재시도한다.

`view.prediction.isConditional`이 참이면 “지금 준비를 시작하면”으로 표시한다. 시계가 실행 기록보다 과거로 이동하면 예상은 null이고 오류를 표시한다. 루틴의 단계 추적은 현재 엔진 계약대로 완료·건너뛰기 즉시 다음 단계에서 시작한다.

이 API는 계획에 선택할 루틴을 전달받는다. 루틴 목록 편집 화면, 기록 조회 화면, 날짜 자동 전환, 위치 감지, 실제 행동 시작 자동 감지는 이 변경에 포함하지 않는다. 다른 날짜를 계획하려면 명시적으로 `configure`한다. 전체 앱 및 실제 기기 연결은 #24·#17에서 별도로 검증한다.

## 명세 대조 보완 (2026-11-07)

같은 목표 날짜의 도착 시각·루틴 수정은 기상 기록을 보존한다. 루틴이 달라지면 이전 종료 실행의 활성 참조만 분리하고 과거 실행은 유지한다. 날짜가 바뀌면 새 기상 회차로 처리한다. 진행 중인 실행 교체 제한은 유지한다.

설정·다시 울림·해제의 OS 적용 의도도 먼저 저장한다. `view.alarmUpdatePending`과 `alarmPendingAt`으로 재실행 후에도 미적용 상태를 확인한다. 대기 중 시각이 null이면 취소, 값이 있으면 그 시각 예약이다. `retryAlarm()`은 원래 계획을 무조건 되살리는 대신 저장된 의도를 재시도한다. 앱 재실행만으로 대기 예약을 자동 적용하지 않으며 화면에서 대상 시각·권한 상태와 함께 재시도 조작을 제공해야 한다. 이미 지나간 대기 시각을 다음 날짜로 넘기지 않는다.

대기 의도가 없는 상태에서 명시적으로 다시 적용할 때도 먼저 예약 또는 취소 의도를 저장한다. 저장 실패 시 OS를 변경하지 않고, 권한 거부·OS 실패 시 재실행 후에도 의도를 확인할 수 있다. 종료는 진행 중 초기화·조작을 기다린 다음 구독을 취소하며 중복 종료 호출도 같은 종료를 기다린다.
