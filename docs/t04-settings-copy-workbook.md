## 2. 화면 구성·입력 라벨

제목은 **시간 설정**. 본문은 아래 순서로 구성하고 **설정 저장** 버튼은 하단 고정 영역에 둔다. 저장 알림이 버튼을 가리지 않게 하고 전체 스크롤·키보드·큰 글자에서 입력과 저장에 접근할 수 있게 한다.

| 순서/묶음 | ID | 모델 필드 | 화면 라벨 | 입력 방식·조건 |
|---|---|---|---|---|
| 1 / 도착 계획 | F01 | arrivalTime | 목표 도착 시각 | 시각 선택, 필수 |
| 2 / 도착 계획 | F02 | travelDuration | 이동 시간 | 시간·분 정수 입력, 합계 0분~24시간 |
| 3 / 수면·기상 계획 | F03 | sleepDuration | 수면 시간 | 시간·분 정수 입력, UI 범위 1분~24시간 |
| 4 / 수면·기상 계획 | F04 | wakeMode | 기상 시각 설정 | 권장 시각 사용 / 직접 지정 |
| 5 / 수면·기상 계획 | F05 | manualWakeTime | 직접 지정할 기상 시각 | 직접 지정 선택 시에만 표시, 이때 필수 |
| 6 / 기상 감지 시간 | F06 | detectionStart | 감지 시작 시각 | 시각 선택, 필수, 시작 포함 |
| 7 / 기상 감지 시간 | F07 | detectionEnd | 감지 종료 시각 | 시각 선택, 필수, 종료 제외 |

기상 방식은 라디오 버튼으로 **권장 시각 사용**, **직접 지정**을 표시한다. 최초 사용은 권장 시각 사용을 초기 선택하고 다른 값은 비워 두는 안을 제안한다. 기존 설정 수정은 저장값을 표시한다. 예시값을 기본값으로 사용하지 않는다.

모드 전환 정책 제안: 권장 모드에서는 수동 시각 입력을 숨기되 기존 값을 유지한다. 직접 지정으로 돌아오면 복원한다. 권장 모드에서는 수동 시각 없이 저장 가능하고 기존 값이 있으면 함께 보존한다. 현재 모델은 이를 허용한다.

## 4. ko-KR 형식·단위

24시간제와 분 단위 입력은 이번 UI의 제안이며 locale이나 모델의 강제 제약은 아니다.

| 항목 | 적용안 |
|---|---|
| 시각 | 24시간제 HH:mm. 예: 00:00, 09:00, 12:00, 23:59 |
| 시각 선택 요소 | 기본 Material ko-KR 현지화(시간 / 분). 오전·오후 선택 없음 |
| 용어 | 하루 중 위치는 시각, 걸리는 기간은 시간 |
| 기간 입력 | 이동·수면 각각 시간·분 두 칸. 접미 단위는 시간 / 분. 좁은 화면에서는 세로 배치 |
| 빈칸과 0 | 두 칸 모두 필수. 30분은 0시간 30분, 이동 없음은 0시간 0분. 빈칸을 0으로 간주하지 않음 |
| 숫자 | 앞뒤 공백 제거 후 음이 아닌 정수. 분은 0~59. 합산 후 전체 범위 검증 |
| 최대값 | 기간은 24시간 0분. 시각은 23:59까지이며 24:00 불가 |
| 수면 최소값 | 모델은 0보다 큰 Duration을 허용. 1분은 분 단위 UI의 최소값 |
| 구간 요약 | 감지 시간: {start}~{end} / 자정 통과: 감지 시간: {start}~다음 날 {end} |
| 필수 표시 | 필드에 필수 표시. 수동 시각은 직접 지정에서만 필수 |
| 미입력 시각 | 시각 선택 |
| 접근성 | 기간 칸 이름: 이동 시간, 시간 / 이동 시간, 분 / 수면 시간, 시간 / 수면 시간, 분 |

기존 기간의 초·마이크로초는 해당 시간을 수정하지 않으면 그대로 보존한다. **기존 {fieldLabel}: {seconds}초. 시간을 수정하면 분 단위로 적용돼요.**로 정확한 값과 편집 단위를 안내한다. 시간 필드를 편집한 경우에만 정수 분 값으로 저장한다.

## 7. 범위 경계·구현 확인

구현 현황: 계획 탭의 `시간 설정`에서 전체 설정을 입력·수정·저장한다. SQLite 조회·저장과 화면 재진입 복원을 연결했다. 모드 전환 시 수동 값은 유지되며 선택기 취소는 기존 값을 바꾸지 않는다. 저장 중 중복 요청을 차단하고 실패 후 입력 유지·재시도를 제공한다. 데스크톱 위젯 테스트에서 실제 DB를 닫고 다시 열어 복원을 검증했으며 Android 실기기 프로세스 종료·재실행 검증은 별도로 남아 있다.

- 루틴 편집은 T05. 총 준비 시간은 루틴에서 얻으며 T04 입력 필드로 추가하지 않는다.
- 계산은 T06, 결과 표시는 T07. 이번 화면에 결과 미리보기를 추가하지 않는다.
- 수동 시각은 알람 계획값이며 실제 기상 기록을 만들지 않는다. 후보 감지는 T08, 알람 예약·취소·권한은 T17이다.
- 감지 구간이 알람을 포함해야 한다거나 수동 시각이 권장보다 빨라야 한다는 제약은 현재 모델에 없다.
- 소리·진동·다시 울림 간격은 현재 AppSettings 입력 필드가 아니다.
- 이슈는 중요한 판단을 사용자 승인 후 PROMPTS.md에 기록하도록 명시한다. 배치·단위·초기값·모드 유지 정책은 검토 초안이며 승인·구현 시 판단 근거를 기록한다.

검토 예시: 도착 09:00 / 이동 0시간 30분 / 수면 8시간 0분 / 감지 07:40~08:00. 자정 통과: 22:00~다음 날 02:00. 예시는 기본값이 아니다. {fieldLabel}, {value}, {start}, {end}는 치환 자리이며 그대로 노출하지 않는다.
