## Android 에뮬레이터 시험

Android API 37의 `emulator-5554`에서 `test_driver/ui_audit_main.dart`를 사용한다. 일반 DB와 다른 `ui_audit_20261110_01.db`를 열고 준비된 예시 데이터만 사용한다. 일반 앱 DB의 초기화·덮어쓰기를 하지 않는다.

```powershell
cd app
flutter run -d emulator-5554 -t test_driver/ui_audit_main.dart --dart-define=UI_AUDIT_DB=ui_audit_example.db
```

점검 진입점은 재시작할 때 저장값·루틴 ID·과거 실행 스냅샷을 `UI_AUDIT_SNAPSHOT` 로그에 출력한다. DB가 처음 생성될 때만 예시를 넣으므로 삭제 후 재시작 시 예시가 다시 생기지 않는다. 점검 종료 후에는 일반 진입점으로 다시 빌드·설치한다.

ADB로 실제 접근성 노드·키보드·터치를 사용했고 각 단계의 저장 결과를 프로세스 재시작 후 네이티브 SQLite 재조회 로그로 비교했다.

- T04: 실제 키보드로 이동 시간을 30→45분으로 수정, 수동 모드와 07:00 선택·저장. 프로세스 종료·재시작 후 45분/manual/07:00 복원 확인.
- T05 등록: DeviceRoutine에 First 10분·Second 5분을 입력하고 위로 이동 후 저장. 재시작 뒤 Second→First 순서·새 ID·합계 15분 유지.
- T05 수정: Seed routine을 EditedSeed로 변경하고 Meal 단계를 위로 옮겨 15→16분 수정. 재시작 뒤 원래 루틴 ID `audit_seed`, 단계 ID `audit_meal`·`audit_wash` 유지 및 합계 36분 확인.
- T05 삭제: 확인 취소 시 목록 유지. 두 점검 루틴 삭제 후 빈 목록 표시, 재시작 뒤 루틴 0개 유지.
- 과거 실행: 등록·수정·삭제 및 각 재시작 후에도 기존 `audit_past`의 이름 Seed routine과 Wash→Meal 스냅샷 유지.
- 정상 앱 복원: 점검을 마친 뒤 일반 진입점 APK를 업데이트 설치하고 실행했다. 일반 앱 DB는 점검에 사용하지 않았다.

위 Android 관측은 이 에뮬레이터와 격리 DB에 대한 결과다. 모든 물리 기기나 모든 프로세스 종료 시점을 검증한 결과로 확장하지 않는다.

## 남는 검증 범위

모든 가능한 OS·장치·사용자 이벤트 조합을 유한한 시험으로 보장하지는 않는다. 위 명세 조건과 재현 가능한 위험 사례를 확인한 범위에서 판정한다.

- 실제 물리 기기의 제조사별 키보드·접근성 서비스·회전 동작, 디스크 가득 참·전원 중단 시점별 시험은 별도다. 닫힌 SQLite·손상 데이터 시험으로 이 모든 상황을 확인했다고 보지 않는다.
- OS가 저장 도중 프로세스를 죽이는 모든 타이밍, 미저장 초안의 프로세스 종료 복구, 기기 간 동기화는 이번 UI의 완료 보장에 포함하지 않는다.
- 알람 예약·취소·권한, 계산 결과·실행·기상 확정은 후속 태스크 범위다.
- PR 분리·원격 이슈 체크박스·활동지의 최종 완료 판단은 이 시험 결과와 구분한다.
