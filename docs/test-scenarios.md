# T12 테스트 시나리오 및 예시 데이터

- **관련 이슈:** #20
- **담당:** 오형석 / **리뷰:** 강동혁
- **관련 문서:** `docs/week-05.md`, `docs/week-07.md`
- **문서 상태:** 테스트 설계 완료 / 실제 실행 전

## 1. 목적 및 범위

아침 기상·루틴 관리 앱의 **설정 → 알람 → 기상 감지·확정 → 루틴 → 예상 도착·지각 계산 → 기록 저장** 흐름을 검증하기 위한 테스트 시나리오와 예시 데이터를 정의한다.

정상 동작과 함께 늦은 기상, 감지 오류, 잘못된 입력, 날짜 변경 및 Android 환경별 예외 상황을 포함한다.

본 문서는 T12의 테스트 설계 산출물이며, 실제 실행과 결함 검증은 T13에서 수행한다. 현재 모든 테스트는 `미실행` 상태이다.

## 2. 공통 데이터 및 테스트 원칙

### 2.1 공통 예시 데이터

| 항목 | 설정값 |
|---|---|
| 목표 도착 시각 | 09:00 |
| 이동 시간 | 30분 |
| 수면 시간 | 8시간 |
| 기상 방식 | 권장 기상 |
| 루틴 | 세면 20분 → 식사 20분 |
| 총 준비 시간 | 40분 |
| 권장 출발 | 08:30 |
| 권장 기상 | 07:50 |
| 권장 취침 | 도착일 전날 23:50 |

**시간 계산 기준**

- 권장 출발 = 목표 도착 − 이동 시간
- 권장 기상 = 권장 출발 − 총 준비 시간
- 권장 취침 = 적용 기상 − 수면 시간
- 예상 도착 = 예상 출발 + 이동 시간
- 예상 지각 = max(0, 예상 도착 − 목표 도착)

별도 조건이 없는 테스트는 공통 데이터를 사용한다. 예상 도착은 설정된 루틴 소요시간대로 진행하며 추가 지연이 없다고 가정한다.

### 2.2 공통 테스트 원칙

- 테스트 시작 전 관련 기상 기록과 예약 알람을 초기화한다.
- 알람 해제와 기상 확정은 구분한다.
- 시간 계산 시 날짜 변경 여부도 확인한다.
- 실제 Android 감지와 개발용 테스트 이벤트를 구분한다.
- 오류 발생 시 앱 종료 및 기존 정상 설정값 손상 여부를 확인한다.
- 실행할 수 없는 테스트는 `BLOCKED`로 표시하고 사유를 기록한다.

### 2.3 구현 규칙 확인 항목

| 항목 | 관련 태스크 | 확인 기준 |
|---|---|---|
| 다시 울림 간격 | T17 | 최종 구현 규칙 |
| 기상 감지 구간 | T08 | 시작·종료 시각 및 경계 포함 여부 |
| 후보 취소 후 재감지 | T08 | 상태 전이 규칙 |
| 기상 확정 후 알람 취소 | T17 | 잔여 예약 처리 규칙 |

미확정 규칙은 실제 구현을 확인한 후 기대 결과에 반영한다.

## 3. 테스트 시나리오

### TC-01. 정상 기상 및 루틴 완료

**조건:** 공통 설정, 실제 기상 07:50

**절차**
1. 공통 설정을 저장하고 알람 발생 여부를 확인한다.
2. 화면 활동으로 기상 후보를 생성하고 확정한다.
3. 세면·식사 루틴을 완료한 뒤 예상 시간과 기록을 확인한다.

**기대 결과**
- 07:50에 예약된 알람이 정상 발생함
- 취침 전날 23:50 / 기상 07:50 / 출발 08:30
- 예상 도착 09:00 / 지각 0분
- 기상 확인 후에만 확정되며 루틴 완료 상태와 실행 기록이 저장됨

### TC-02. 늦은 기상 및 예상 지각

**조건:** 공통 설정, 실제 기상 08:20

**절차**
1. 08:20에 기상 후보를 생성하고 확정한다.
2. 루틴 진행 후 예상 시간과 저장 기록을 확인한다.

**기대 결과**
- 예상 출발 09:00 / 도착 09:30 / 지각 30분
- 확정 전에는 실제 기상 기록이 저장되지 않음
- 루틴 진행 결과와 예상 시간이 정상 반영됨

### TC-03. 알람 해제 및 다시 울림

**조건:** 최초 알람 07:50, 다시 울림 간격은 T17 기준

**절차**
1. 07:50에 예약된 알람이 발생하는지 확인한 후 해제하고, 기상 확정 여부를 확인한다.
2. 별도 알람에서 다시 울림을 선택한다.
3. 재알림 시각·중복 여부와 기상 확정 후 예약 상태를 확인한다.

**기대 결과**
- 알람 해제만으로 기상이 확정되지 않음
- 다시 울림이 T17 규칙대로 동작하며 중복 발생하지 않음
- 기상 확정 후 잔여 알람이 정의된 규칙에 따라 처리됨
- 예약 실패 시 오류 또는 제한 상태를 확인할 수 있음

### TC-04. 수동 기상 시각 설정

**조건:** 수동 기상 07:00, 수면 8시간

**절차**
1. 기상 방식을 수동으로 변경하고 07:00을 저장한다.
2. 취침 시각·알람 예약값·설정 유지 여부를 확인한다.
3. 권장 기상 방식으로 다시 전환한다.

**기대 결과**
- 수동 기상 07:00 / 취침 전날 23:00
- 저장 후 수동 설정 유지
- 권장 방식 전환 시 기상 07:50 적용

### TC-05. 기상 후보 취소

**조건:** 감지 활성화, 기상 미확정

**입력:** 화면 활동 07:45 → 후보 취소 → 07:50 재활동

**절차**
1. 07:45에 화면 활동 신호를 발생시키고 기상 후보 및 확인 요청이 표시되는지 확인한다.
2. 후보를 취소한 뒤 기상 상태·저장 기록·루틴 시작 여부를 확인한다.
3. 07:50에 다시 활동 신호를 발생시킨다.

**기대 결과**
- 첫 번째 신호로 기상 후보가 생성되고 확인 요청이 표시되지만 자동 확정되지 않음
- 후보 취소 후 미확정 상태 유지
- 취소된 시각이 확정 기상으로 저장되지 않고 루틴이 시작되지 않음
- 이후 신호는 T08의 재감지 규칙에 따라 처리됨

**확인 사항:** 두 신호가 T08의 유효 감지 구간에 포함되는지 실행 전 확인한다.

### TC-05B. 기상 감지 구간 경계값

**조건:** T08의 감지 구간 및 경계 포함 여부 확정

| 신호 시점 | 확인 항목 | 상태 |
|---|---|---|
| 구간 시작 직전 | 구간 밖 신호 처리 | 미실행 |
| 구간 시작 시각 | 시작 경계 포함 여부 | 미실행 |
| 구간 종료 시각 | 종료 경계 포함 여부 | 미실행 |
| 구간 종료 직후 | 구간 밖 신호 처리 | 미실행 |

**기대 결과:** 각 신호가 T08의 감지 구간 규칙에 따라 처리되며, 구간 밖 신호로 잘못된 확정 기록이 생성되지 않는다.

**실행 전 확인:** T08 규칙 확정 후 각 신호의 실제 테스트 시각을 기록하고 실행한다.

### TC-06. 반복 화면 켜짐 및 중복 방지

**조건:** 감지 활성화, 기존 후보·확정 기록 없음

**입력:** 화면 활동 07:50, 07:51, 07:52

**절차**
1. 첫 활동으로 후보를 생성한 후 추가 신호를 발생시킨다.
2. 확인 요청의 중복 여부를 확인하고 기상을 한 번 확정한다.
3. 저장 기록을 확인한다.

**기대 결과**
- 후보 및 확인 요청이 불필요하게 중복 생성되지 않음
- 확정 기상 기록은 한 건만 저장됨
- 추가 신호로 확정 시각이 임의 변경되지 않음

### TC-07. 감지 누락 및 수동 입력

**조건:** 자동 감지 누락, 수동 기상 08:10

**절차**
1. 자동 감지 후보가 없는 상태에서 08:10을 수동 입력한다.
2. 루틴을 진행하고 예상 시간과 저장 기록을 확인한다.

**기대 결과**
- 기상 08:10 / 출발 08:50 / 도착 09:20 / 지각 20분
- 수동 기상 시각과 루틴 기록이 정상 저장됨
- 수동 입력이 자동 감지 성공으로 잘못 기록되지 않음

### TC-08. 잘못된 입력 및 오류 처리

**조건:** 기존 정상 설정값 저장, 각 입력은 독립적으로 테스트

| ID | 테스트 입력 | 기대 결과 | 상태 |
|---|---|---|---|
| 08-1 | 목표 도착 시각 누락 | 오류 안내, 저장 방지 | 미실행 |
| 08-2 | 이동 시간 누락 | 오류 안내, 저장 방지 | 미실행 |
| 08-3 | 음수 이동 시간 | 오류 안내, 저장 방지 | 미실행 |
| 08-4 | 음수 루틴 소요시간 | 오류 안내, 저장 방지 | 미실행 |
| 08-5 | 잘못된 시간 형식 | 오류 안내, 저장 방지 | 미실행 |
| 08-6 | 필수 루틴 정보 누락 | 오류 안내, 저장 방지 | 미실행 |
| 08-7 | 오류 수정 후 정상 입력 | 정상 저장 | 미실행 |

**공통 기대 결과:** 앱이 비정상 종료되지 않고 기존 정상 설정이 유지되며, 오류 수정 후 정상 저장할 수 있다.

**확인 사항:** 필수 입력 및 허용 범위는 최종 UI·데이터 계약을 기준으로 판단한다.

### TC-09. 자정 경계 및 날짜 변경

**조건:** 이동 30분, 준비 40분, 수면 8시간

**기대 결과**

- B는 출발 시각이 자정, C는 출발 날짜가 전날로 계산됨
- 날짜가 잘못 이동하지 않고 저장 후에도 유지됨

### 4.2 판정 기준

- **미실행:** 아직 테스트하지 않음
- **PASS:** 실제 결과와 기대 결과 일치
- **FAIL:** 실제 결과와 기대 결과 불일치
- **BLOCKED:** 기능 미구현 또는 환경 제약으로 실행 불가

실제 테스트 시 실행일, 기기·OS, 앱 버전 또는 커밋, 실제 결과, 재현 절차, 결함 이슈를 기록한다. T13에서는 실행 환경 정보를 별도로 관리하고 필요시 결과표에 관련 열을 추가한다.

## 5. T13 통합 검증 연계

T13에서는 본 문서의 **주요 테스트 10개와 추가 경계값 테스트 1개**를 활용해 전체 기능을 검증한다.

실제 Android 감지와 개발용 테스트 이벤트는 구분하며, 결함 발견 시 재현 절차를 기록하고 수정 후 재검증한다. T08·T17 등의 구현 규칙이 변경되면 관련 기대 결과를 갱신한다.
