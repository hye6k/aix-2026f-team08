# T12 테스트 시나리오 및 예시 데이터

- **관련 이슈:** #20
- **담당:** 오형석 / **리뷰:** 강동혁
- **관련 문서:** `docs/week-05.md`, `docs/week-07.md`
- **문서 상태:** 테스트 설계 완료 / 실제 실행 전

## 1. 목적 및 범위

아침 기상·루틴 관리 앱의 **설정 → 알람 → 기상 감지·확정 → 루틴 → 예상 도착·지각 계산 → 기록 저장** 흐름을 검증하기 위한 테스트 시나리오와 예시 데이터를 정의한다.

정상 동작과 함께 늦은 기상, 감지 오류, 잘못된 입력, 날짜 변경 및 Android 환경별 예외 상황을 포함한다.

본 문서는 T12의 테스트 설계 산출물이며, 실제 실행과 결함 검증은 T13에서 수행한다. 현재 모든 테스트는 `미실행` 상태이다.

## 2. 공통 데이터 및 테스트 원칙

### 2.1 공통 예시 데이터

| 항목 | 설정값 |
|---|---|
| 목표 도착 시각 | 09:00 |
| 이동 시간 | 30분 |
| 수면 시간 | 8시간 |
| 기상 방식 | 권장 기상 |
| 루틴 | 세면 20분 → 식사 20분 |
| 총 준비 시간 | 40분 |
| 권장 출발 | 08:30 |
| 권장 기상 | 07:50 |
| 권장 취침 | 도착일 전날 23:50 |
| 기상 감지 시작 시각 | 07:40:00 (시작 포함) |
| 기상 감지 종료 시각 | 08:00:00 (종료 제외) |

감지 구간은 `07:40:00 이상 ~ 08:00:00 미만`이며, 현재 모델 기준(시작 포함·종료 제외)을 따른다. 이 구간은 TC-01·TC-03(03-3)·TC-05·TC-05B·TC-06에 적용한다. T08에서 규칙이 달라지면 2.3의 확정 필요 항목과 함께 갱신한다.

**시간 계산 기준**

- 권장 출발 = 목표 도착 − 이동 시간
- 권장 기상 = 권장 출발 − 총 준비 시간
- 권장 취침 = 적용 기상 − 수면 시간
- 예상 도착 = 예상 출발 + 이동 시간
- 예상 지각 = max(0, 예상 도착 − 목표 도착)

별도 조건이 없는 테스트는 공통 데이터를 사용한다. 예상 도착은 설정된 루틴 소요시간대로 진행하며 추가 지연이 없다고 가정한다.

### 2.2 공통 테스트 원칙

- 테스트 시작 전 관련 기상 기록과 예약 알람을 초기화한다.
- 알람 해제와 기상 확정은 구분한다.
- 시간 계산 시 날짜 변경 여부도 확인한다.
- 실제 Android 감지와 개발용 테스트 이벤트를 구분한다.
- 오류 발생 시 앱 종료 및 기존 정상 설정값 손상 여부를 확인한다.
- 독립 사례로 표시된 항목은 사례마다 후보·기록·예약·권한 상태를 초기화한 뒤 수행한다.
- 실행할 수 없는 테스트는 `BLOCKED`로 표시하고 사유를 기록한다.

### 2.3 구현 규칙 확인 항목

본 문서의 시각·간격 값 중 명세로 확정되지 않은 값은 아래 표에 구분해 둔다. **확정 필요** 항목은 실제 구현을 확인한 뒤 해당 TC의 입력 시각과 기대 결과를 함께 갱신한다.

| 항목 | 관련 태스크 | 문서 적용 값 | 구분 |
|---|---|---|---|
| 기상 감지 구간 | T08 | 07:40 이상 ~ 08:00 미만 (시작 포함·종료 제외) | 현재 모델 기준, T08 최종 확인 |
| 다시 울림 간격 | T17 | 5분 (예시값) | **확정 필요** |
| 다시 울림 재예약 시각 기준 | T17 | 다시 울림 선택 시각 + 5분 (테스트용 가정) | **확정 필요** |

| 기상 확정 후 잔여 알람 | T17 | 확정 시 남은 예약 취소 (기대 동작) | **확정 필요** |
| 후보 취소 후 재감지 대기 시간 | T08 | 5분 (예시값) | **확정 필요** |

## 3. 테스트 시나리오

### TC-01. 정상 기상 및 루틴 완료

**조건:** 공통 설정, 실제 기상 07:50

**절차**

1. 공통 설정을 저장하고 알람 발생 여부를 확인한다.
2. 화면 활동으로 기상 후보를 생성하고 확정한다.
3. 세면·식사 루틴을 완료한 뒤 예상 시간과 기록을 확인한다.

**기대 결과**

- 07:50에 예약된 알람이 정상 발생함
- 취침 전날 23:50 / 기상 07:50 / 출발 08:30
- 예상 도착 09:00 / 지각 0분
- 기상 확인 후에만 확정되며 루틴 완료 상태와 실행 기록이 저장됨

### TC-02. 늦은 기상 및 예상 지각

**조건:** 공통 설정, 실제 기상 08:20

**감지 구간:** 08:20은 공통 감지 구간(07:40~08:00) 밖이므로, 이 사례에서는 후보 생성이 가능하도록 감지 구간을 `07:40 이상 ~ 08:30 미만`으로 설정한다. (T08 규칙에 따라 조정 필요 시 갱신)

**절차**

1. 08:20에 화면 활동으로 기상 후보를 생성하고, 확정 전에 표시되는 예상 시간을 확인한다.
2. 기상을 확정한다.
3. 루틴 진행 후 예상 시간과 저장 기록을 확인한다.

**기대 결과**

- 후보 생성 직후·확정 전: "지금 준비를 시작하면 09:30 도착 · 30분 지각"이라는 조건부 예상이 표시됨
- 확정 전에는 실제 기상 기록이 저장되지 않음
- 확정 후 예상 출발 09:00 / 도착 09:30 / 지각 30분
- 루틴 진행 결과와 예상 시간이 정상 반영됨

### TC-03. 알람 해제 및 다시 울림

**조건:** 최초 알람 07:50, 다시 울림 간격 5분(예시값, 2.3의 확정 필요 항목 — T17 확정 값이 다르면 아래 시각을 교체)

각 사례는 독립적으로 수행하며, 사례 시작 전 예약·후보·기록을 초기화한다.

| ID | 입력 | 기대 결과 | 상태 |
|---|---|---|---|
| 03-1 | 07:50 알람 발생 → 해제 (다시 울림 선택 안 함), 이후 화면 활동 없음 | 기상 미확정 · 확정 기록 0건 · 재예약 없음 (07:50~08:00 사이 추가 알람 미수신) | 미실행 |
| 03-2 | 07:50:00 알람 발생 → 07:50:05 다시 울림 선택 | 조작 시각 기준 07:55:05에 재예약 · 07:55:05에 알람 1회 발생 (중복 없음) · 기상 미확정 | 미실행 |
| 03-3 | 07:50:00 알람 발생 → 07:50:05 다시 울림 선택 (07:55:05 재예약) → 07:52:00 화면 활동으로 후보 생성 → 07:52:10 기상 확정 | 07:52:10 기상 확정 · 잔여 예약 0건 · 07:55:05~08:00:05 알람 미수신 (관측 구간 5분) | 미실행 |

**공통 기대 결과**

- 알람 해제만으로 기상이 확정되지 않음 (03-1)
- 다시 울림이 재예약 시각에 1회만 동작함 (03-2)
- 기상 확정 후 남은 예약이 취소되어 재예약 시각에 알람이 울리지 않음 (03-3)

**확인 사항:** 알람 해제 후 자동 재예약 여부, 다시 울림 간격·재예약 시각 기준, 확정 후 잔여 알람 처리는 T17 최종 규칙으로 확정한 뒤 시각·기대값을 갱신한다. 재예약 시각의 허용 오차도 구현 및 실행 환경을 확인해 판정 전에 정한다. 예약 실패 시 오류·제한 상태 표시는 TC-10B에서 확인한다.

### TC-04. 수동 기상 시각 설정

**조건:** 수동 기상 07:00, 수면 8시간

**절차**

1. 기상 방식을 수동으로 변경하고 07:00을 저장한다.
2. 취침 시각·알람 예약값·설정 유지 여부를 확인한다.
3. 권장 기상 방식으로 다시 전환한다.

**기대 결과**

- 수동 기상 07:00 / 취침 전날 23:00
- 저장 후 수동 설정 유지
- 권장 방식 전환 시 기상 07:50 적용

### TC-05. 기상 후보 취소 및 재감지

**조건:** 감지 활성화, 기상 미확정, 공통 감지 구간(07:40 이상 ~ 08:00 미만)

**적용 설정:** 후보 취소 후 재감지 대기 시간 5분 (예시값, 2.3의 확정 필요 항목). 07:46에 취소하면 07:51까지 대기한다.

**입력**

| 신호 | 시각 | 구분 |
|---|---|---|
| ① 화면 활동 | 07:45:00 | 최초 신호 |
| (후보 취소) | 07:46:00 | 취소 시각 |
| ② 화면 활동 | 07:48:00 | 재감지 대기 중 (대기 종료 전) |
| ③ 화면 활동 | 07:52:00 | 재감지 대기 종료 후 |

**절차**

1. 07:45에 신호 ①을 발생시키고 기상 후보 및 확인 요청이 표시되는지 확인한다.
2. 07:46에 후보를 취소하고 기상 상태·저장 기록·루틴 시작 여부를 확인한다.
3. 07:48에 신호 ②를 발생시키고 후보·확인 요청 생성 여부를 확인한다.
4. 07:52에 신호 ③을 발생시키고 후보·확인 요청 생성 여부를 확인한다.

**기대 결과**

- 07:45: 기상 후보 생성 · 확인 요청 표시 · 자동 확정되지 않음
- 07:46 취소 후: 미확정 상태 유지 · 확정 기록 0건 · 루틴 미시작 · 07:45가 확정 기상으로 저장되지 않음
- 07:48 (대기 중): 후보·확인 요청 생성되지 않음
- 07:52 (대기 후): 후보·확인 요청 1건 생성 · 자동 확정되지 않음

**확인 사항:** 재감지 대기 시간이 T08에서 다르게 확정되면 07:48·07:52의 시각과 기대값을 갱신한다. 대기 시간이 없는 규칙이라면 신호 ②부터 후보가 생성되어야 한다.

### TC-05B. 기상 감지 구간 경계값

**조건:** 감지 활성화, 공통 감지 구간 `07:40:00 이상 ~ 08:00:00 미만` (시작 포함·종료 제외, 현재 모델 기준)

**수행 방식:** 각 입력은 독립 사례로 수행한다. 사례마다 이전 후보·확인 요청·확정 기록이 없는 상태로 초기화하고, 후보·확인 요청이 생성되어도 사용자가 확정하지 않은 채 생성 여부만 관찰한다.

| ID | 입력 시각 | 구간 판정 | 기대 후보 | 기대 확인 요청 | 기대 확정 기록 | 상태 |
|---|---|---|---|---|---|---|
| 05B-1 | 07:39:59 (시작 직전) | 구간 밖 | 생성되지 않음 | 생성되지 않음 | 없음 | 미실행 |
| 05B-2 | 07:40:00 (시작 시각) | 구간 안 (시작 포함) | 생성됨 | 표시됨 | 없음 (확정 전) | 미실행 |
| 05B-3 | 07:59:59 (종료 직전) | 구간 안 | 생성됨 | 표시됨 | 없음 (확정 전) | 미실행 |
| 05B-4 | 08:00:00 (종료 시각) | 구간 밖 (종료 제외) | 생성되지 않음 | 생성되지 않음 | 없음 | 미실행 |
| 05B-5 | 08:00:01 (종료 직후) | 구간 밖 | 생성되지 않음 | 생성되지 않음 | 없음 | 미실행 |

**기대 결과:** 구간 밖(05B-1, 05B-4, 05B-5)에서는 확정 기록뿐 아니라 후보와 확인 요청도 생성되지 않는다. 구간 안(05B-2, 05B-3)에서는 후보와 확인 요청이 생성되지만 확정 전에는 기록이 저장되지 않는다.

**실행 전 확인:** 초 단위 경계값은 개발용 테스트 이벤트의 시각 주입 기능을 이용해 검증하는 것을 원칙으로 한다. 해당 기능이 제공되지 않으면 `BLOCKED`로 기록하고 실행 방법을 T13에서 별도로 확정한다. 개발용 이벤트와 실제 Android 감지 결과는 구분해 기록한다. T08에서 경계 포함 여부가 달라지면 05B-2, 05B-4의 기대값을 갱신한다.

### TC-06. 반복 화면 켜짐 및 중복 방지

**조건:** 감지 활성화, 기존 후보·확정 기록 없음

**입력:** 화면 활동 07:50, 07:51, 07:52

**절차**

1. 첫 활동으로 후보를 생성한 후 추가 신호를 발생시킨다.
2. 확인 요청의 중복 여부를 확인하고 기상을 한 번 확정한다.
3. 저장 기록을 확인한다.

**기대 결과**

- 후보 및 확인 요청이 불필요하게 중복 생성되지 않음
- 확정 기상 기록은 한 건만 저장됨
- 추가 신호로 확정 시각이 임의 변경되지 않음

### TC-07. 감지 누락 및 수동 입력

**조건:** 자동 감지 누락, 수동 기상 08:10

**절차**

1. 자동 감지 후보가 없는 상태에서 08:10을 수동 입력한다.
2. 루틴을 진행하고 예상 시간과 저장 기록을 확인한다.

**기대 결과**

- 기상 08:10 / 출발 08:50 / 도착 09:20 / 지각 20분
- 수동 기상 시각과 루틴 기록이 정상 저장됨
- 수동 입력이 자동 감지 성공으로 잘못 기록되지 않음

### TC-08. 잘못된 입력 및 오류 처리

**조건:** 기존 정상 설정값 저장, 각 입력은 독립적으로 테스트
