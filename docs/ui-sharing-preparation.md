# T04·T05 UI 공유 준비: 브랜치 분리

현재 브랜치: `feat/25-settings-routines-ui`.
관련 이슈: #25(T04), #26(T05).
목적: 시간 설정·루틴 입력 및 편집 UI와 공통 오류 처리·검증 자료를 T03 작업 공간에서 분리해 공유 준비한다.

## 분리 상태

- 원본 작업 공간을 변경하지 않는 별도 Git worktree를 생성했다.
- 오늘 구현·점검한 UI 소스, 테스트, 문서 19개 파일을 복사하고 원본과 SHA-256 해시를 대조했다.
- 분리 시 원본에 이미 스테이징돼 있던 `app/test/domain/models_test.dart` 변경은 복사하지 않았다. 원본의 내용과 스테이징 상태를 그대로 보존했다.
- 공통 앱 조립 코드, 확인창 및 T04·T05 통합 시험이 함께 변경됐으므로 오늘의 UI 작업은 한 브랜치에 묶었다. T03 저장 구현 파일을 UI 변경으로 복사하거나 수정하지 않았다.
- 브랜치 분리 직후에는 미커밋 상태였다. 후속 공유 단계에서는 이 작업 공간의 UI 소스·테스트·문서를 별도 한국어 커밋으로 나누어 제출하고 원본 모델 테스트 변경은 제외한다.

## 기준 커밋과 선행 의존성

- UI 기준: T03 브랜치 `feat/8-sqlite-store`의 `5dbbc683744bc134f43670535fec81e19439b988`.
- 분리 시 fetch로 확인한 `origin/main`: `3467e32352b35487a3462c32dbe790aa048dae2a`.
- 위 main에는 T03 SQLite 저장 구현이 아직 포함돼 있지 않았다. 필수 저장 구현을 빼거나 UI PR에 중복 포함하지 않도록 T03 커밋 위에 UI 브랜치를 만들었다.
- PR 준비 시 T03이 미병합이면 기준 브랜치를 `feat/8-sqlite-store`로 지정하고 의존성을 명시한다. T03 병합 후 최신 main으로 기반을 옮겨 UI 변경만 리뷰되도록 정리한다.
- 2026-11-11 공유 준비 시 T03은 [PR #27](https://github.com/hye6k/aix-2026f-team08/pull/27)에서 미병합 상태임을 확인했다. UI Draft PR은 위 T03 브랜치를 기준으로 한다.
- 이는 6주차의 최신 main 기준 규칙에 대한 선행 의존성 처리다. 현재 브랜치를 바로 main 대상의 독립 PR로 설명하지 않는다.

## 검증 자료

원래 통합 작업 공간에서 수행한 171건 시험·Android 관측은 [UI 점검 보고서](t04-t05-ui-audit.md)에 있다. 원래 모델 테스트의 별도 스테이징 변경은 이 브랜치에 없다. 분리한 작업 공간에서 캐시된 의존성 복원, 정적 분석, 기본 모델 테스트 5건을 확인했고 2026-11-11 공유 전 전체 171건 재실행과 소스·테스트·점검 진입점 포맷 검사가 통과했다. 의존성 버전과 lockfile은 변경하지 않았다.

Draft PR은 #25·#26과 이 점검 보고서를 연결한다. 물리 기기 검증과 T03 병합 후 main 기반 통합 확인을 남은 작업으로 명시하며 이슈 전체를 완료 처리하지 않는다.
