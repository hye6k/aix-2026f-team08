## 테스트 3개 / Three tests (대상 / 검증 내용)

아래는 수업 이후 공유 테스트 브랜치에서 수행한 검증입니다.

1. **루틴 일정의 필수 입력** — 기상 시각을 선택하지 않으면 일정 저장이 차단되고, 선택해 저장하면 홈에 반영되는 것을 Flutter 화면 테스트로 확인했습니다.
2. **이동 이력에 따른 권장 시각** — 같은 경로의 이동 시간이 30분, 35분, 90분이고 도착 마감이 오전 9시일 때 중앙값 35분으로 **08:25 출발 권장**을 표시하는 것을 확인했습니다. 준비 시간 40분을 반영한 **07:45 기상 권장**도 확인했습니다. 기록을 제외해 유효 이동 기록이 3건 미만이 되면 출발 권장이 사라지고, 다시 포함하면 복원됐습니다.
3. **Android 알림과 기상 알람** — [#42의 갤럭시 실기기 검증](https://github.com/hye6k/aix-2026f-team08/issues/42#issuecomment-7060688153)에서 즉시 발송한 취침 알림을 잠금 해제 전에 펼쳐 달 이미지를 확인했습니다. 후속 확인에서는 잠금화면 상단에 아이콘이 표시됐고, 큰 이미지는 기본으로 펼쳐지지 않았습니다. 에뮬레이터에서는 출발 테스트 알림을 받았고, 화면을 끈 상태에서 테스트 기상 알람이 울렸습니다. 화면을 직접 켜자 잠금화면에 기상 알람이 표시됐습니다.

**후속 검증 예정**

- GPS 자동 기록은 실기기에서 잠금 중 감지가 이어지는지와 위치 오차로 잘못 기록되는지를 확인할 예정입니다.
- 실제 루틴의 예약 알림과 기상 알람은 잠금 상태 발송, 조기 출발 시 취소, 기상 확인 후 다음 알람 예약, 기상 화면 자동 켜짐을 확인할 예정입니다. [공유 테스트 이슈 #44](https://github.com/hye6k/aix-2026f-team08/issues/44)

## AI 코드리뷰 관점 2개 / 주요 지적 / Two review perspectives

1. **이상치가 출발 안내에 미치는 영향** — 같은 경로의 유효 기록이 3건 이상이면 최근 최대 5건의 중앙값을 사용합니다. 평소와 다른 이동은 기록을 보존한 채 추천 계산에서 제외할 수 있습니다.
2. **예시 데이터의 검증 범위** — 예시 모드에서도 출발·도착을 시험할 수 있도록 실제 기록과 예시 기록을 분리했습니다. 개발자 옵션의 가상 시각으로 출발·도착과 준비 시간 표시를 확인했습니다.

## 받아들이지 않은 지적과 이유 / Findings rejected and why

AI가 초기 설정에서 예상 이동 시간을 직접 입력받는 방식을 제안했습니다. 초기 입력 부담을 줄이고 실제 이동 이력으로 안내를 계산한다는 방향에 따라 채택하지 않았습니다. 기록이 부족한 동안에는 도착 마감 시각을 표시합니다.
